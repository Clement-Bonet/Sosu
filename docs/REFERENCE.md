## std.channel

Channels between threads (spec §5.6), with the effect `threads` (spec §7.4). A channel copies the values it carries (`Send`: without pointers), in a queue of a fixed capacity. It is itself a value without pointer, given to the threads that use it.

### struct `Channel<T: Send>`

```sosu
pub struct Channel<T: Send>
```

- `pub bool send(T value) uses threads`  
  Copies `value` in, waiting while the channel is full; false if it is closed.
- `pub T? receive() uses threads`  
  The next value, waiting while the channel is empty; none once it is closed and empty.
- `pub void close() uses threads`  
  No more values: the receivers get those left, then none.
- `pub void free() uses threads`  
  Releases the channel, once the threads that use it are joined.

### `new`

A channel of `capacity` values of `T`.

```sosu
pub Channel<T> new<T: Send>(ui64 capacity) uses threads requires capacity > 0
```

## std.cli

The options and arguments of a command, and its help written from them (spec §8.2).      cli.Command* c = cli.command(&arena, "count", "Counts the words of files.");     c.flag("verbose", 'v', "print each file");     c.option("min", 'm', "N", "only the words of N letters or more", "1");     c.argument("file", "the first file to read");     c.rest("files", "the other files");     match (c.parse(os.args(&arena))) {         ok(m) => ... m.flag("verbose"), m.value("min"), m.argument("file"), m.rest() ...         err(e) => io.print("{}", c.message(&arena, e)),  // the help, or what is wrong     }  Written `--name value`, `--name=value`, `-n value` or `-nvalue`; flags without value join (`-vq`). `--` ends the options: what follows are arguments, even if they start with `-`. `-h` and `--help` give `HelpWanted`.

### enum `CliError`

```sosu
pub enum CliError {
    HelpWanted,  // -h or --help
    UnknownOption(str name),  // as written: "--colour", "-x"
    MissingValue(str name),  // an option without its value
    NotAFlag(str name),  // --verbose=yes: a flag takes no value
    MissingArgument(str name),  // fewer arguments than declared
    TooManyArguments(str value),  // the first one beyond those declared
}
```

### class `Command`

A command: its options and arguments, declared before `parse`.

```sosu
pub class Command
```

- `pub void flag(str name, char short, str help)`  
  An option without value, false unless given: `--name` or `-s`.
- `pub void long_flag(str name, str help)`  
  The same, without a short name.
- `pub void option(str name, char short, str value_name, str help, str default_value)`  
  An option with a value, `default_value` unless given; the help shows it as `value_name`.
- `pub void long_option(str name, str value_name, str help, str default_value)`
- `pub void argument(str name, str help)`  
  An argument that must be given, after those declared before it.
- `pub void rest(str name, str help)`  
  The arguments after the declared ones, as many as given (none too).
- `pub Matches*!CliError parse(str[] args)`  
  Reads `args` (without the name of the program: `os.args`).
- `pub str help(Arena* arena)`  
  The help: how the command is written, what it does, its arguments and its options.
- `pub str message(Arena* arena, CliError e)`  
  What to print after `parse` failed: the help, or the error and how to get the help.

### class `Matches`

What `parse` read.

```sosu
pub class Matches
```

- `pub bool flag(str name)`  
  Whether the flag `name` was given.
- `pub str value(str name)`  
  The value of the option `name`: the last one given, or its default.
- `pub str[] values(str name)`  
  Every value given to the option `name`, in order (`-I a -I b`); none given: an empty view.
- `pub bool has(str name)`  
  Whether the option or the flag `name` was given (else `value` is its default).
- `pub str argument(str name)`  
  The declared argument `name`.
- `pub str[] rest()`  
  The arguments after the declared ones.

### `command`

A command named `name` (as the help shows it), doing what `about` says.

```sosu

```

## std.log

Messages with a level, to the error output or to a file (spec §8.2). On Android, the error output is the log of the system (`adb logcat -s sosu`, spec §11.5). A line is "2026-10-28T07:43:05Z WARN message", the time in UTC; without timestamps, "WARN message". Writing a message allocates nothing.

### enum `Level`

```sosu
pub enum Level {
    Debug,
    Info,
    Warn,
    Error,
    Off,  // nothing is written
}
```

### struct `Logger`

Where messages go, and from which level.

```sosu
pub struct Logger
```

- `pub void debug(str message) uses io, time`
- `pub void info(str message) uses io, time`
- `pub void warn(str message) uses io, time`
- `pub void error(str message) uses io, time`
- `pub bool enabled(Level at)`  
  Whether a message of `at` would be written: to skip building one that would not.
- `pub void write(Level at, str message) uses io, time`  
  Writes `message` at the level `at`, if it is enabled.
- `pub void close() uses io`  
  Closes the file of a logger made by `to_file`.

### `console`

## std.map

Values found by their key, in the arena given at its creation (spec §5.4). Open addressing with linear probing: a key is placed at its hash, or after it at the first free slot. When three quarters of the slots are used, they move to twice as many.

### class `HashMap<K: Hash, V>`

```sosu
pub class HashMap<K: Hash, V>
```

- `pub void put(K key, V value)`  
  Gives `key` the value `value`, in place of the one it had.
- `pub V? get(K key)`
- `pub V*? at(K key)`  
  The place of the value of `key`, to change it there; none if it has none.
- `pub bool has(K key)`
- `pub V? remove(K key)`  
  Takes `key` away, and gives its value. The keys placed after it move back, so that each stays reachable from its hash.
- `pub usize len()`
- `pub void clear()`
- `pub K[] keys(Arena* into)`  
  Its keys, in no particular order: a copy in `into`.
- `pub V[] values(Arena* into)`  
  Its values, in the order of `keys`: a copy in `into`.

### `new`

```sosu

```

### `run`

Runs the program `command[0]` (looked for in the folders of PATH) with the other elements as its arguments, waits for its end, and gives its exit code and its output; its errors go to those of this program. ## std.sort

Sorting views in place, and binary search in sorted ones (spec §8.2). `sort` and `sort_by` are an introsort: a quicksort, insertion sort for short runs, and a heapsort when the quicksort goes too deep, so they take O(n log n) at worst and no memory; they are not stable. `stable_sort_by` keeps the order of equal elements, with a merge sort that takes `n` elements of room in an arena. The order is given by `less(a, b)`: true when `a` goes before `b`. It must be a strict order (`less(a, a)` false), else the result is in some order but not sorted.

## std.thread

Threads (spec §5.6), with the effect `threads` (spec §7.4). A thread runs a function on a copy of a value, with an arena of its own; it shares no memory with the others (`Send`), and talks to them through channels (std.channel).

### class `Thread<T: Send, R: Send>`

A thread started by `spawn`: `join` waits for its end and gives what its function returned.

```sosu

```

- `pub R join() uses threads`  
  Waits for the end of the thread, then gives its result (again, if called twice).

### `spawn`

Runs `work(arena, value)` on a new thread, with an arena of its own (freed when `work` returns). `work` is a function or a lambda without captures: a closure would read the variables of this thread. The `Thread` is created in `arena`; join it before freeing it.

```sosu
pub Thread<T, R>* spawn<T: Send, R: Send, uses E>(Arena* arena, fn(Arena*, T) -> R uses E work, T value) uses threads, E
```
